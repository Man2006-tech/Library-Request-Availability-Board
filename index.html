How it works

  1. Search

    Find books by title, author or category and filter by availability.

  2. Request or queue

    Available books can be requested. Unavailable books let you join a first-in, first-out hold queue.

  3. Librarian decides

    A librarian approves or rejects each pending request. Approved books get a due date.

  4. Renew or return

    Renew eligible loans, or return the book so the next student in the queue is served.

Browser client vs. server (HTTP)

Everything here runs in your browser. Each action sends a simulated HTTP-style request through a Promise with a short setTimeout delay. A real version would send the same request with fetch() to a server, which would check who you are, apply the rules and answer with a status code and JSON.

Runs in the browser (this assignment)

  • Rendering pages, forms and layout (HTML/CSS)
  • Search filtering, queue and renewal logic (JavaScript)
  • Form validation and error messages
  • Sample data in a JavaScript array (saved in localStorage)

Would run on a server (later assignments)

  • Real authentication and authorization
  • A database holding books, users and requests
  • Enforcing the rules so they cannot be bypassed
  • Integration with a real library system (not claimed here)
